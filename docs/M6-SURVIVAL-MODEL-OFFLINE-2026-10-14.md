## What was implemented and tested

- Two server-ready, clamped `0..100` *need* ledgers (thirst/hunger; rising is worse) and the existing `0..Max` stamina ledger. All six named activity rates use **real seconds / config's per-minute values**, not a phase or accelerated Studio test clock. Environment/wound multipliers are data inputs for an eventual server authority, never client positions or client-supplied results. Invalid activity, negative/non-finite or excessive dt fail without mutation.
- Cross-meter smoothstep coupling follows `SurvivalConfig.Coupling.Threshold=70`, `Width=5`, `ThirstFromHunger=.20` and `HungerFromThirst=.15`. Config also lists `Modifiers.StarvedThirst=1.20` and `ParchedHunger=1.15`: those are **mirrors of the SAME maximum effect**, not another multiplier. The constructor checks exact parity and refuses disagreement instead of silently compounding thirst by 1.44×. A red test caught a missing arithmetic grouping in the initial local prototype; it was corrected before delivery.
- Config-declared threshold and timed debuffs compose numeric effects multiplicatively (health drains add), with unique screen/audio cues sorted by authored Priority. Added/removed debuff definitions work without named service-code branches. `Bleeding` is an input condition; this module neither applies wound HP loss nor makes a second Humanoid health writer. `Sick` expires from its configured timer.
- Stamina drain and regeneration obey authored rates, a real 1.5-second post-sprint delay, need/debuff regeneration penalties, and a timed `Exhausted` cue only after **more than 3 seconds actually at zero** (not before the exact depletion time). A midpoint regression ensures that when the delay ends halfway through a one-second step, only the eligible **half-second** regenerates; continuous attempted sprinting at zero does not silently refill stamina. The duplicate `Stamina.ExhaustionDuration` and `Debuffs.Exhausted.Trigger.timed` values are asserted equal, so a later config edit cannot silently choose one timer. `Collapse` is a **pure candidate predicate** over needs and health, not a fall/noise/remote side effect.
- **Pure consumption arithmetic** is available only by a deliberately named `applyVerifiedConsumable` post-validation method: clamped needs for authored food/water, deterministic server-supplied sick roll, and declared action time/AIR intensity returned only as metadata. It performs **no** inventory removal, timed action, noise emission or HP write; unknown items and Health-managed bandage/medkit return an error without state mutation. An InventoryService must commit an owned item before any eventual server-only call.
- Dedicated **54/54** executable pure-model checks in `tools/vitriol/survival-model.luau` exercise determinism, data-driven debuffs, cue deduplication, coupling, timed Sick and Exhausted, verified-consumable meter changes, the collapse predicate, invalid inputs, and boundaries. The new module is in the pure smoke bundle; the full local gate now includes its own check. No runtime UI/Parts, owner data persistence, or gameplay Script was created.
- The new **unwired server adapter** has **57/57** headless checks in `tools/vitriol/survival-service.luau`: per-UserId isolation and run-local reconnect continuity; refusal of stale/forged Player objects and dead, permadead or dawn-waiting lives; explicit server activity/environment samplers; HealthService-owned bleed/HP overriding environment claims; post-step `metersAllowRegen` per live player; invalid sampler fail-closed; detached owner snapshots revoked. A final integration segment uses the **real** Bootstrapped `HealthService:metersAllowRegen` seam with a headless Player, verifying post-step gating and no extra HP write. An explicitly invoked headless adapter now emits the authored one-shot `VIBRATION 0.9` at a verified body position into the **real** NoiseField (count/sample asserted); a missing emitter/time, dead HealthService life, missing body or rejected insertion leaves the request pending without inserting an impulse. It sends no Remote, creates no Instance and registers no heartbeat/Cadence slot. Initial local test revealed a Lua `and nil or error` return-value trap; explicit error/no-error branches fixed it before the 57/57 passing run. The full gate is **49/49**.

- A separate **pure collapse timeline** (`Shared/SurvivalCollapse.luau`) has **24/24** deterministic tests at `tools/vitriol/survival-collapse.luau`. A verified server eligibility verdict arms one 1.5-second onset; the authored **`VIBRATION 0.9` is an at-most-once retrievable *event request*** when the fall boundary is crossed, retained across long ticks until taken. The authored 8-second crawl interval follows and then holds; canceling a departed body's pending request does not erase its collapse state; **this is not a NoiseField emission, ragdoll, control lock or recovery implementation**. It does not auto-reset or invent a food/water recovery policy.
- The adapter has explicit, **unwired** `beginCollapse`/`advanceCollapse`/`takeFallForNoise` entry points. They verify current Health and Player identity, reject an unauthorized or healthy request, cap dt, keep stamina at zero and derive a one-time fall request from the **currently attached, finite server body root**—not a stale/hidden player clue. Missing root leaves the request pending; the request is also bound to the original character identity, so a replacement character cannot advance or emit an earlier body's fall. Disconnect drops that body's pending request so reconnect cannot emit ghost noise at a new body, but does not erase critical needs or the collapse phase. Snapshot cues recalculate current Health/phase rather than reusing stale flags. These are server-owned request semantics, plus an **offline-only** real NoiseField emission seam: `pulse` arms at the END of the candidate-crossing tick, then advances the full 1.5-second onset on subsequent real server ticks and emits once when the body has a valid current position. It still has **no live Bootstrap/Cadence wiring**, movement/ragdoll enforcement or recovery. A later live integration must provide verified activity/environment samplers, enforce crawl/controls and define recovery from verified consumption. The gate includes both fixtures and remains **49/49**.

- The new pure **timed consumption transaction** (`Shared/SurvivalConsumeAction.luau`) has **25/25** focused tests. An explicitly server-verified food/water item starts its authored 2–3 s action; invalid dt cannot fast-forward it, a grab/item loss cancels it, and "Ready" still does not credit meters. At commit, `SurvivalModel:consumableDefinition` preflights the server sick roll and item data **before** the injected, atomic, non-yielding `consumeOwned` callback removes one genuinely owned item. Failed validation/ownership leaves needs unchanged; a successful commit applies the item **once**, including Sick if rolled. Reentrant/double commits cannot duplicate food. The **pure** transaction returns AIR intensity as metadata only. The separately tested **unwired server adapter** can emit it into a real headless NoiseField after successful fake-inventory commit; there is still no real InventoryService, prompt or client intent wired. Health-managed bandages/medkits are rejected to keep HealthService the sole HP writer. This work did not change authored rates, short phases, geometry, or live cadence shares.

- A NEW **offline server consumption seam** in `SurvivalService` has **25/25** headless checks at `tools/vitriol/survival-consume-service.luau`. It requires injected, server-only `Inventory:hasOwned` / synchronous atomic `consumeOwned`, `CanConsume` (grabs/life/item validity), `RollSick`, a NoiseField and server Time; absent dependencies fail closed. It owns an action per UserId and physical character, advances the authored timer on an explicit server pulse, cancels on interruption/death/character swap/disconnect, and calls the model only after a successful one-item claim. Successful commits emit one authored `AIR` impulse into the **real headless NoiseField** at the verified action-completion position/time; a rejected insertion retains one pending event and blocks more items until it can be retried (no unbounded queue). Test coverage includes another player's inventory, invalid Sick rolls before removal, failed claims, duplicate prevention, Health regen, and no new Instance/Remote/Heartbeat. The inventory used here is a **test fake**: none of these entry points is routed to clients, Bootstrap or Cadence.

## Important pacing mismatch — leave tuning unresolved

`docs/05-SURVIVAL.md` §7 expects **Parched at about 9 minutes** and **Collapse at about 16 minutes** of mixed activity without consumption. Existing `SurvivalConfig.ActivityDrain.Walking` is thirst **0.80 per real minute**, hunger **0.42 per real minute**. From sated, nine walking minutes yield just **7.2 thirst / 3.78 hunger** (Parched threshold is 80). Even an impossible uninterrupted 16-minute baseline sprint, before any stamina restriction, yields only **33.6 thirst / 15.2 hunger** and no collapse. Some extreme condition multipliers could change these rates, but they are not specified as the ordinary acceptance scenario. The config, short owner-approved Studio phases (`NightBaseSeconds=70`), debuff thresholds and desired 9/16-minute targets **were not changed**. This is a product tuning decision, not a math bug to paper over with a hidden speed multiplier. The current model implements the **actual authored config**, while the design acceptance criterion remains unmet.
