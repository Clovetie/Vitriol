# Agent operating rules — Vitriol

1. Use **Clovetie/Vitriol `main` only** as code baseline. `docs/00-VISION.md`, `docs/01-ARCHITECTURE.md`, `ROADMAP.md` and `INTEGRATION.md` define the game; an attached Tunneling brief is a different project.
2. Activate the [Vitriol Studio skill](.agents/skills/vitriol-studio/SKILL.md) for all Roblox Studio tasks. `tools/studio_bridge.py` is the legacy bridge client; never assume newer arenarobloxbridge `/api/tool` methods are installed.
3. All **custom UI and game Instances are Edit-mode authored**. No runtime `Instance.new`, `Clone`, generated PlayerGui/ScreenGui, dynamically fabricated remote, on-demand gore/debris/creature, or auto-repair. Property animation/reuse and Roblox engine-created avatars are fine. Add authored instances with a guarded, idempotent editor job, then validate counts/classes and *absence of duplicates*. Modify code and tests before pushing to Studio.
4. Run `bash tools/install-luau.sh` and `node tools/vitriol-quality-gate.js --src code` (including official Luau compilation and static-content gate), then Studio `verify_static_vitriol.lua`, `parity`, and a **fresh Play** test. A green headless test ≠ playable Studio proof. The server owns gameplay/health; client inputs go through `NetContract`.
5. Keep credentials in environment only; report evidence as counts/path/commit, never token. Save Studio place and push the local checkout to GitHub only when authenticated/authorized; otherwise state both limitations explicitly.
6. After each change follow the closed loop: inspect → choose one failure/feature → implement in the matching Explorer path + Edit-mode assets → static tests → sync selected scripts → readback parity → Play/Output/perf → update `INTEGRATION.md`/roadmap/next-agent prompt. Do not declare a Play acceptance criterion without Play evidence.
